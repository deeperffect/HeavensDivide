# Enemy death presentation

Standard enemies inherit EnemyDeathComponent from EnemyBase. HP death still enters HandleDeath once. It stops behavior, AI, movement, attack montages and collision before notifying listeners. OnEnemyDied, OnEnemyDeath, marks/status cleanup, healing drops, XP pickups, and spawner death/destruction tracking remain intact. The component calls DestroyAfterDeath after the dissolve; this project currently destroys enemies rather than returning dead actors to a pool.

Select EnemyDeathComponent in an enemy Blueprint's Components panel to override Death Niagara System, Niagara Spawn Offset (world space; Z is height), Death Sound, Death Sound Concurrency, Dissolve Duration, Dissolve Parameter Name, Dissolve Start Value, and Dissolve End Value. Defaults are 0.25 seconds, DissolveAmount, 0 to 1. Native defaults reuse NS_Hit_Basic_Once and MS_Ninja_Impact as the initial burst/sound. Clear either asset to omit it. Use one-shot, non-looping assets. Empty concurrency uses a shared 16-voice group across enemy types; Niagara uses AutoRelease pooling and sounds use fire-and-forget playback.

The component ticks only during presentation. It covers visible mesh components owned by the enemy, including multiple slots and attached weapon components. UI is excluded. Existing MIDs are reused, and shared material assets are never changed at runtime. Overlay materials that cannot dissolve are cleared at death. Mesh transforms are never scaled or collapsed.

Existing standard enemy body and weapon materials have been migrated, so they need no manual dissolve setup. Their collapse function calls/parameters were removed, and masked opacity now uses a noise threshold controlled by DissolveAmount (0 fully visible, 1 fully gone). Base color, normal, and other surface inputs are preserved.

For a new material, use Masked blend mode, add a scalar parameter named DissolveAmount with default 0, and connect a noise threshold to Opacity Mask. Match the endpoints so 0 shows the entire mesh and 1 hides it completely. The migrated materials use mask = noise.R * 0.98 + 0.01 - DissolveAmount + 0.333, with clip threshold 0.333. Every visible material slot needs this support; unsupported slots remain visible until actor cleanup. Overlay materials must support the same parameter or will be removed at death. Assets using a different parameter name can override the component setting.

FinalBossBase retains its existing death montage and completion callback. Boss-category enemies bypass the standard component. BeginDeathPresentation is the custom presentation hook; a custom boss sequence should finish with DestroyAfterDeath. The default boss fallback delay is 3 seconds. Gameplay rewards/events must remain in HandleDeath, not in this presentation hook. A future true actor pool should override DestroyAfterDeath and explicitly add a respawn/reset contract before reusing dead actors; the current component deliberately allows only one death per actor lifetime.

## Dissolve fix and quick setup

The initial migration connected Opacity Mask but left UE 5.8's inline UseConstant flag enabled on that input. Its constant 1 overrode the connected graph, so DissolveAmount changed without affecting the rendered mesh. Tools/fix_enemy_dissolve_masks.py disabled that override on all 12 enemy materials, with backups in Saved/Backups/EnemyDissolveMaskFix. The migration now clears it explicitly too.

Restart Unreal after this asset correction to reload the saved materials. Open BP_EnemyGrunt and select EnemyDeathComponent. Leave Dissolve Parameter Name = DissolveAmount, Start = 0, End = 1. Grunt's existing 2-second duration was preserved so the effect is easy to inspect. Once satisfied, change Duration to 0.25 seconds for a fast death. MF_Dissolve is not used by this system and does not need editing.

DissolveAmount is a visibility threshold against a grayscale noise texture: 0 shows the entire enemy; intermediate values remove more patches; 1 removes everything. The component animates that number and performs actor cleanup afterward.

The new render regression Tools/verify_enemy_dissolve_render.py checks the actual saved Grunt Blueprint mesh under D3D12. It passed with visible pixel counts [3922, 1383, 0] at DissolveAmount [0, 0.5, 1]. Run it with UnrealEditor-Cmd -run=pythonscript, PythonScriptPlugin and EditorScriptingUtilities enabled, and -AllowCommandletRendering -noraytracing. Images and results are in Saved/Automation/DissolveRendering. This catches the constant-mask defect that checking material parameter values alone missed.
